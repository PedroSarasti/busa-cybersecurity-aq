## Escalada de privilegios

Ahora vamos a escalar privilegios, lo primero que debemos validar es que puede ejecutar `lin` con permisos de root, con el siguiente comando:

```bash
sudo -l
```

![Resultado de sudo -l mostrando permisos sobre /bin/tar](/writeups/tryhackme/bounty_hacker/image%209.png)

Con esto nos damos cuenta que `lin` puede ejecutar `/bin/tar` como root. Esto es explotable con GTFOBins:

```bash
sudo tar -cf /dev/null /dev/null --checkpoint=1 --checkpoint-action=exec=/bin/bash
```

- Desglose del comando
    
    ---
    
    **`sudo tar`**
    Ejecuta tar con privilegios de root, porque `sudo -l` nos mostró que lin puede correr `/bin/tar` como root.
    
    ---
    
    - **`cf /dev/null /dev/null`**
    - `c` → crear un archivo tar
    - `f /dev/null` → el archivo de salida es `/dev/null` (la papelera del sistema, descarta todo)
    - `/dev/null` → el archivo a comprimir (también la papelera, no importa)
    
    Básicamente le decimos a tar que "comprima nada en ningún lado" — solo es para que el comando sea válido sintácticamente.
    
    ---
    
    - **`-checkpoint=1`**
    Los checkpoints son puntos de control que tar usa para mostrar progreso. Al poner `=1` le decimos que ejecute un checkpoint después de procesar **cada 1 registro**, o sea, inmediatamente.
    
    ---
    
    - **`-checkpoint-action=exec=/bin/bash`**
    Esta es la parte clave. Le dice a tar que cuando llegue a un checkpoint, ejecute una **acción**. En este caso la acción es ejecutar `/bin/bash`.
    
    Como tar está corriendo como **root** gracias a sudo, la bash que abre también es de **root**.
    
    ---
    
    ## Resumen del flujo
    
    ```
    sudo tar → corre como root
        → llega al checkpoint (inmediatamente)
        → ejecuta /bin/bash como root
        → obtienes shell de root 🎯
    ```
    
    Esta técnica está documentada en **GTFOBins** (`https://gtfobins.github.io/gtfobins/tar/`) que es una base de datos de binarios Unix que pueden ser abusados para escalar privilegios.
